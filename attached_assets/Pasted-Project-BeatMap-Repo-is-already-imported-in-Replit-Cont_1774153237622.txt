Project: BeatMap
Repo is already imported in Replit.

Context:
BeatMap is an AI music intelligence app with:
- Frontend: Next.js + React + TypeScript + Tailwind
- Backend: FastAPI + Python
- Current status:
  - link analysis exists
  - YouTube metadata works
  - Gemini/Grok-based analysis is at least partially working
  - the app already has analysis cards like hook window, mood shifts, scene fit, voiceover-safe sections, and alternative tracks
Goal:
Turn BeatMap from “interesting AI demo” into a genuinely useful everyday creator tool.

CRITICAL PRODUCT DIRECTION
Do not make this feel like a developer tool.
Design and wording must be understandable for users with very little technical knowledge.
Everything on the homepage and analysis pages should feel simple, obvious, and practical for:
- creators
- editors
- influencers
- small businesses
- marketers
- students
- people making reels/shorts/TikToks
- users who do not understand terms like “hook window,” “waveform,” “metadata,” or “MCP”

Use plain-English labels everywhere.
Example:
- Instead of only “Hook Window”, show “Best opening moment”
- Instead of only “Voiceover-safe sections”, show “Best parts to talk over”
- Instead of only “Scene-fit categories”, show “Best use cases”
- Instead of only “Alternative tracks”, show “Similar tracks you can try”

Also add short helper text under advanced concepts so the UI teaches the user naturally.

DO NOT JUST ADD RANDOM FEATURES.
Implement the following as a coherent product upgrade.

FEATURE 3 — BEST CUT GENERATOR
==================================================

Objective:
Automatically tell users the best segment of the song for common video lengths.

This is one of the most useful everyday features.

Add a new analysis section called something like:
- “Best cuts for your video”
or
- “Best sections to use”

Show recommended cuts for:
- 15 seconds
- 30 seconds
- 45 seconds

Each cut should include:
- start time
- end time
- why this section works
- use case fit
- optional confidence
- optional note if based on metadata-only vs audio-assisted reasoning

Requirements:
1. Extend backend response schema to include best cut recommendations.
2. The logic should consider:
   - edit preset
   - energy arc
   - opening strength
   - likely payoff section
   - voiceover suitability where relevant
3. Return a structured array, for example:
   - durationLabel
   - start
   - end
   - title
   - reason
   - confidence
4. The frontend should render these beautifully as cards or timeline chips.
5. Add plain-language explanations like:
   - “Best 15-second version for a quick reel”
   - “Best 30-second version for storytelling”
6. Add “Copy timestamps” or “Copy this cut” button if feasible.
7. If the system is in metadata-only mode, explain it honestly:
   - “This cut is estimated from metadata and AI reasoning”
   - not fake certainty

FEATURE 4 — VOICEOVER-SAFE GUIDANCE
==================================================

Objective:
Make it easy for users to know where they can talk over the music.

This is a high-value real-world feature.

Requirements:
1. Upgrade the current voiceover section so it is more practical and understandable.
2. Rename or dual-label the section in plain language, for example:
   - “Best parts to talk over”
   - subtitle: “These sections are less busy and may work better for narration.”
3. Return multiple segments with:
   - start/end time
   - safety level (great / okay / risky)
   - reason
4. If audio evidence is available, use it.
5. If only metadata/AI inference is available, clearly label that.
6. Add an optional filter or note based on preset:
   - for ads and explainers, prioritize cleaner speaking space
   - for hype edits, speaking space may matter less
7. Use user-friendly color and wording.
8. Avoid too much jargon like “spectral density” or “vocal masking” in the UI.
9. If you want, add a tiny legend:
   - Great for talking
   - Could work
   - Music may compete with speech

FEATURE 5 — SHOT-PLAN GENERATOR
==================================================

Objective:
Turn music analysis into an actual editing plan.

This is a standout differentiator.

Add a new section called something like:
- “Suggested shot plan”
- “How to cut your video to this track”

For a selected edit type and a track, generate a simple sequence such as:
- 0:00–0:03 → opening hook / attention grabber
- 0:04–0:08 → setup shots
- 0:09–0:14 → reveal / key visual
- 0:15–0:21 → emotional buildup
- 0:22–0:30 → payoff / CTA / ending

Requirements:
1. Extend backend analysis response to include shot plan steps.
2. Each step should include:
   - label/title
   - start
   - end
   - suggested visual purpose
   - short explanation
3. The shot plan must adapt to edit preset.
Examples:
- Product ad → reveal, details, CTA
- Travel montage → opening scenery, motion shots, scenic payoff
- Emotional storytelling → memory setup, emotional peak, reflective ending
- Gym hype edit → fast intro, intensity build, drop, power finish
4. Frontend should render this in a way that feels easy to follow:
   - numbered timeline
   - cards
   - vertical step list
5. Use plain language with helpful hints.
6. Add a “Copy shot plan” option if feasible.
7. Keep the tone practical, not overly poetic.

FEATURE 6 — TRACK COMPARISON
==================================================

Objective:
Let users compare multiple songs for one creative goal.

This is a major time-saver because people often test many songs manually.

Build a compare mode where a user can:
- add 2 to 3 tracks
- choose one edit preset
- compare which track is best for that purpose

Requirements:
1. Add a compare workflow on the frontend:
   - a “Compare tracks” entry point
   - let user paste 2–3 links
   - reuse the edit-type preset selector
2. Create backend compare support, either:
   - dedicated endpoint like POST /api/compare
   - or reuse existing analysis and aggregate results cleanly
3. The comparison output should rank the tracks on practical dimensions like:
   - best opening moment
   - best 15-second cut
   - best for voiceover
   - strongest emotional payoff
   - best overall fit for selected edit type
4. Show a clear winner summary:
   - “Best overall for product ad”
   - “Best opening hook”
   - “Best if you need to talk over the music”
5. Keep the comparison understandable for beginners.
6. Use side-by-side cards or a simple score layout.
7. Add notes explaining why one track is better for the chosen use case.

Important:
Do not rely on meaningless scores alone.
Always explain the ranking in plain English.
